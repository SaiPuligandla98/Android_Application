The one switch: if versionCode is not increased, nothing ships.

LIMITATIONS & TRAPS — read before releasing

  • The signing key can never change. A different key = INSTALL_FAILED_UPDATE_INCOMPATIBLE. Lose the .jks and no device can ever be updated again — each must be uninstalled and reinstalled by hand. Keep 2 backups.
  • Debug and release are different apps. Different applicationId and different key. Moving a device from debug to release needs one uninstall.
  • Forgetting to bump versionCode means CI publishes nothing. No error, just no update.
  • CDN cache ~5 minutes. A device checking immediately after publish may still receive the old manifest. Wait, then re-open.
  • Background check is "at least 6 h", not exactly. Android batches it. Opening the app checks instantly.
  • Notifications off (Android 13+) = update alerts silently dropped. Settings screen warns when this is the case.
  • "Install unknown apps" not granted = install cannot start.
  • Rollback only works on debuggable builds. Android blocks installing an older version over a newer one; on release builds the app must be uninstalled first (data is erased).
  • Repo must be public for devices to download without a token. A token embedded in an APK is readable by anyone.
  • Never hand-edit ota/update-manifest.json. CI owns it on master. Editing it on a branch causes merge conflicts — always keep master's copy.
